# speech-to-text

핸드폰으로 녹음한 m4a를 한국어 텍스트로 옮기는 CLI. 결과는 입력 파일과 같은 폴더에 생긴다.
전사는 faster-whisper(large-v3, GPU), 화자 구분은 sherpa-onnx를 쓴다. 전부 로컬에서 돌고
외부로 오디오를 보내지 않는다.

## 쓰는 법

```bash
.venv/bin/stt "/mnt/c/Users/cyyoo/Recordings/회의.m4a"
```

Windows 탐색기에서 복사한 경로를 그대로 붙여넣어도 된다(`C:\Users\...`, 따옴표 포함).
Claude Code에서는 어느 폴더에 있든 `/stt <경로>` 로 부를 수 있다.

결과 파일 두 개가 입력 파일 옆에 생긴다.

```
회의.txt            순수 텍스트. 화자·시간 없이 문단만 정리
회의.timeline.txt   [00:01:23] 화자1: ... 형태
```

`--json` 을 주면 `회의.json` 도 함께 만든다(발화별 start/end/speaker, 다른 도구에 넘길 때).

이미 결과 파일이 있으면 덮어쓰지 않고 건너뛴다. 손으로 고쳐둔 txt를 날리지 않기 위한 것으로,
다시 만들려면 `--force` 를 준다.

## 자주 쓰는 옵션

```
--no-diarize        혼자 말한 메모. 화자 구분을 건너뛴다(더 빠름)
--speakers 4        참석자 수를 알 때. 자동 추정보다 정확하다
--threshold 0.6     화자가 너무 잘게 나뉘었을 때 올린다(기본 0.55, 내리면 더 잘게 나뉜다)
--no-vad            결과가 너무 짧게 나왔을 때 (아래 참고)
--model medium      급할 때. 기본 large-v3 가 가장 정확하다
--device cpu        GPU를 다른 작업에 쓰고 있을 때
--encoding utf-8    BOM 없이 저장 (기본은 utf-8-sig)
```

## 결과가 너무 짧게 나오면

배경음악이 크거나 마이크가 멀면 무음 판정(VAD)이 사람 말을 잡음으로 보고 버린다.
실제로 BGM이 깔린 영상에서는 문장 앞부분이 통째로 잘려나갔고, `--no-vad` 로 돌리니 살아났다.
말소리로 인식된 구간이 전체의 25% 미만이면 그 사실을 알려주니, 그때 이렇게 다시 돌린다.

```bash
.venv/bin/stt "회의.m4a" --no-vad --force
```

조용한 녹음은 `--vad-threshold 0.3` 처럼 기준만 낮춰도 된다.

반대 방향의 부작용도 있다. `--no-vad` 로 돌리면 음악이나 긴 무음 구간에서 whisper가
없는 말을 만들어낸다(실측: BGM만 있는 100초에서 "한글자막 by 한효정", "다음 영상에서 만나요"가
나왔다). 그래서 기본은 VAD를 켜두고, 잘려나간 것 같을 때만 끄는 쪽이 낫다.

## 속도

RTX 5070 Laptop(8GB)에서 large-v3 GPU 전사 + CPU 화자분리로 실측한 값이다.

```
5분(말이 빽빽한 파일)   55초   → 5.4배속   1시간이면 대략 11분
1분 40초(말이 적은 파일) 5초   → 19배속    무음이 많으면 훨씬 빠르다
```

첫 실행은 모델(약 3GB)을 내려받으므로 더 걸린다. GPU를 못 쓰면 CPU로 자동 폴백하는데
그때는 몇 배 느려지니 `--model small` 을 쓰는 게 낫다.

## 하지 않는 일

용어 사전이나 오탈자 후보정은 하지 않는다. 사내 약어(PMIC, SSIR, EVT 같은)는 whisper가
소리 나는 대로 적어놓으니 그 교정은 별도로 한다. 요약·회의록 작성도 이 도구의 일이 아니다.
